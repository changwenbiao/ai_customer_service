# 远程调试指南（Go + Python，Docker）

本文说明如何在容器里以调试模式运行 `go` 与 `agent`(Python) 服务，并用 IDE 远程调试。
适用于本地开发排查问题，**不要用于生产环境**。

- Go：Delve headless，端口 `127.0.0.1:2345`（GoLand / VS Code）
- Python：debugpy 端口 `127.0.0.1:5678`（VS Code；PyCharm 2026.x 用「Attach to DAP」）

## 1. 涉及文件

| 文件 | 作用 |
| --- | --- |
| `../../go_service/Dockerfile.debug` | Go 调试镜像：`-gcflags="all=-N -l"` 关闭内联与优化，内置 `dlv`，headless 启动 |
| `../../python_agent/Dockerfile.debug` | Python 调试镜像：安装 `debugpy`，以 `debugpy --listen 0.0.0.0:5678` 启动 |
| `../../docker-compose.debug.yaml` | 覆盖层：把 `go` / `agent` 换成调试 Dockerfile，并暴露调试端口（仅回环地址） |
| `../../docker-compose.yaml` | 基础编排（redis / mysql / postgres / qdrant / agent / go / nginx），本身不含调试配置 |

`../../docker-compose.debug.yaml` 是覆盖层，单独使用无效，必须与 `docker-compose.yaml` 通过多个 `-f` 合并加载。

## 2. 启动命令

以下命令均在仓库根目录执行。

### 2.1 全部服务都以调试模式启动（go + agent）

```bash
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build
```

### 2.2 只调试 Go

```bash
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build go
```

### 2.3 只调试 Python Agent

```bash
# debugpy 监听 127.0.0.1:5678，VS Code 与 PyCharm「Attach to DAP」都连这个地址
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build agent
```

### 2.4 恢复成生产版

```bash
# 两个都恢复
docker compose up -d --build go agent

# 只恢复某一个
docker compose up -d --build agent
```

### 2.5 可选：连同监控组件一起启动

```bash
docker compose --profile observability up -d
```

可观测性组件（Prometheus / Grafana / Loki / Jaeger）默认不启动。

## 3. 启动后验证

```bash
# 业务是否正常（应返回 200）
curl -i http://localhost:8080/api/auth/tenants

# Agent 是否正常（agent 没有映射到宿主机端口，进容器验证）
docker compose exec agent python -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:8000/docs',timeout=3).status)"

# 调试端口是否在监听
lsof -iTCP:2345 -sTCP:LISTEN   # Go / dlv
lsof -iTCP:5678 -sTCP:LISTEN   # Python / debugpy
```

两个调试端口都只绑定在宿主机回环地址，禁止改成 `0.0.0.0`——调试端口无认证、无加密。

容器日志里应能看到：

```
# go
API server listening at: [::]:2345

# agent
# debugpy 的监听提示：Listening on 0.0.0.0:5678
```

## 4. IDE 连接

### 4.1 GoLand（Go）

1. `Run` → `Edit Configurations` → `+` → `Go Remote`
2. Host 填 `127.0.0.1`，Port 填 `2345`
3. 直接 `Debug` attach（服务已在容器内运行，无需 IDE 启动进程）

### 4.2 VS Code（Go）

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Attach to Docker (dlv)",
      "type": "go",
      "request": "attach",
      "mode": "remote",
      "host": "127.0.0.1",
      "port": 2345,
      "substitutePath": [
        { "from": "${workspaceFolder}/go_service", "to": "/build" }
      ]
    }
  ]
}
```

### 4.3 VS Code（Python Agent）

需安装 Python 扩展（新版调试器类型为 `debugpy`）：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Attach to Docker (debugpy)",
      "type": "debugpy",
      "request": "attach",
      "connect": {
        "host": "127.0.0.1",
        "port": 5678
      },
      "pathMappings": [
        { "localRoot": "${workspaceFolder}/python_agent", "remoteRoot": "/app" }
      ]
    }
  ]
}
```

### 4.4 PyCharm 2026.x（Python Agent，「Attach to DAP」）

先说明一个容易踩的坑：**免费版里没有「Python Debug Server」**——该配置（`PyRemoteDebugConfiguration`）属于 Professional 模块，Community / 免费版加载的 `python-ce` 插件中不含此类。
替代方案是 2025.3 起内置的 `Python DAP Debugger` 插件，用其中的 `Attach to DAP` 直接连 debugpy（debugpy 本身就是 DAP 服务端）。

1. 起调试容器（见 2.3，默认就是 debugpy 模式）：

```bash
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build agent
```

2. PyCharm：`Run` → `Edit Configurations` → `+` → 选择 **Attach to DAP**（列表里可能显示为「Attach to …」，可直接搜索 `DAP`）
   - `Remote address`：`127.0.0.1:5678`
   - `Path Mappings`：Local `python_agent` ↔ Remote `/app`

3. 点 `Debug` 启动该配置，控制台出现连接成功的提示后，断点即生效。

排错：

- 列表里找不到 `Attach to DAP`：`Settings` → `Plugins` 确认 `Python DAP Debugger` 插件已启用（2026.x 默认启用）。
- 连接被拒：先确认容器在跑且 `lsof -iTCP:5678 -sTCP:LISTEN` 有输出。
- 断点灰色 / 不命中：检查 Path Mappings 是否为 `python_agent` ↔ `/app`。
- PyCharm Professional 用户有更省事的路子：直接用 Docker Compose 解释器在容器内调试，无需 attach。

### 4.5 路径映射（关键）

容器内源码路径与本机不一致时，断点会显示为**灰色、无法命中**。

- Go：镜像在 builder 阶段 `WORKDIR /build` 编译，DWARF 路径是 `/build/...`，需要把本机 `go_service` 映射到 `/build`。
- Python：镜像把源码复制到 `/app`，需要把本机 `python_agent` 映射到 `/app`。

验证方式：在入口处打一个断点，用浏览器触发对应接口，命中即映射正确。

## 5. 注意事项

- **改代码必须重新构建镜像**：调试版没有热重载（Go 无 air、Python 未开 uvicorn reload），改完需重新执行 `--build`。
  - 想省掉 Python 的重复构建，可临时把源码挂进容器：`volumes: - ./python_agent:/app`，改完 `docker compose restart agent` 即可。
- **断点命中时请求会超时**：Go 进程被 Delve 暂停，此时经过 nginx 的请求会返回 502，属于正常现象，继续运行即恢复。
- **debugpy 不加 `--wait-for-client`**：容器启动即开始服务，IDE 可以随时 attach；若希望停在第一行，需要额外等待客户端（此时 `agent` 健康检查会一直不通过，`go` 也会因 `depends_on` 卡住）。
- `../../docker-compose.debug.yaml` 未设置 `image`，恢复生产版时记得重新 `--build`，否则容器内还是调试二进制。
- 不建议用 `docker compose down -v` 来「重启环境」，它会删除 MySQL / PostgreSQL / Qdrant / Redis 的全部数据卷。
- `../../.env` 请使用 LF 换行，CRLF 会让变量值尾部带上不可见的 `\r`，从文件复制密码时容易出现 MySQL 认证失败。

## 6. 命令速查

```bash
# 全量启动（go + agent 均为调试版）
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build

# 只重建 go（调试版）
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build go

# 只重建 agent（调试版，VS Code / PyCharm「Attach to DAP」都连 5678）
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build agent

# 回到生产版
docker compose up -d --build go agent

# 看日志 / 进容器
docker compose logs -f agent
docker compose exec agent sh
```
