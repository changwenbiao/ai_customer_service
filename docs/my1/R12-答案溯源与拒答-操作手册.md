### 0.3 术语对齐（面试也会问）

- **Grounding（接地）**：回答的事实来自检索到的原文，而不是模型参数记忆。
- **Citation（引用）**：正文 `[1]` 与来源列表一一对应，编号可校验。
- **Abstention / 拒答**：资料不足时明确说"不知道/查不到"，并引导转人工。
- **Groundedness 校验**：判断"回答是否被引用片段支持"，不是判断"回答对不对"。

## 第一章 Step 1：检索结果结构化 + 引用采集

### 1.1 为什么不直接把 JSON 返回给模型

- 模型对 JSON 的字段遵循不稳定，容易漏字段、编字段；
- 编号文本（`[1] xxx`）最接近模型的自然引用习惯，prompt 约束成本最低；
- 但程序又需要结构化数据（doc_id、标题、分数）来落库和前端展示。
- 所以拆成两份：**给模型的是编号文本，给程序的是 ContextVar 里的结构化列表**。

### 1.2 数据结构

```python
Citation = {
    "index":   int,     # 全局编号，正文 [n] 与之对应
    "doc_id":  str,     # 文档 uuid，可回溯 kb_documents
    "title":   str,     # 文档标题
    "section": str,     # 标题路径（R11 实验 E 产出的 section）
    "snippet": str,     # 原文前 200 字，前端折叠展示
    "score":   float,   # 检索/重排分数，仅用于调试与阈值分析
}
```

### 1.3 为什么用 ContextVar 而不是全局 list

`/agent/chat` 与 `/agent/chat/stream` 是并发的，工具函数内部拿不到"这次请求"的局部变量；全局 list 会串请求。
`contextvars.ContextVar` 在 asyncio 任务内有独立副本，天然按请求隔离，无需透传参数。

### 1.4 改造 [tools.py](file:///Users/changwenbiao/PycharmProjects/ai_customer_service/python_agent/tools.py)

在文件顶部（`_tenant_var` / `_thread_var` 附近）增加：

```python
from contextvars import ContextVar

# 单次请求内累积的引用；ContextVar 保证并发请求互不污染
_citations_var: ContextVar[list[dict]] = ContextVar("kb_citations", default=[])


def reset_citations() -> None:
    """每次 /agent/chat 或 /agent/chat/stream 入口调用一次"""
    _citations_var.set([])


def get_citations() -> list[dict]:
    return list(_citations_var.get())


def _append_citations(pairs: list[tuple]) -> list[int]:
    """把本次命中的 (Document, score) 追加进引用列表，返回它们在正文中的编号"""
    current = _citations_var.get()
    start = len(current)                      # 跨多次 search_kb 调用继续编号
    for i, (doc, score) in enumerate(pairs, start=1):
        meta = doc.metadata or {}
        current.append({
            "index": start + i,
            "doc_id": meta.get("doc_id", ""),
            "title": meta.get("title", ""),
            "section": meta.get("section", ""),
            "snippet": (doc.page_content or "")[:200],
            "score": round(float(score), 4),
        })
    _citations_var.set(current)
    return [c["index"] for c in current[start:]]
```

### 1.7 踩坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 正文编号从 [1] 跳到 [3] | 前一次检索命中了但被模型忽略 | 正常，编号按"检索到"分配，不按"用到"分配；前端展示全部来源即可 |
| 两次 search_kb 后引用重复 | 同一文档被两次检索命中 | `_append_citations` 内按 `doc_id+page_content` 去重，或前端按 doc_id 合并 |
| rerank 后编号与相关性不一致 | 编号按重排后的顺序分配 | 这是预期行为：`[1]` 始终是"最相关的那条" |
| ContextVar 在后台线程里为空 | 线程池任务不会自动继承 context | 检索在协程内完成；rerank 已用 `to_thread` 只处理纯计算，不读取 ContextVar |

## 第二章 Step 2：强制引用 Prompt

### 2.1 三条硬约束（缺一不可）

1. **只能依据工具返回的资料作答**，禁止使用参数记忆补全价格、时效、政策。
2. **每个结论后必须标 `[n]`**，编号必须来自资料，禁止虚构编号，禁止 `[0]`、超出范围的编号。
3. **资料里没有就直说不知道**，不猜测，并引导转人工；只覆盖部分问题时只答覆盖部分。

### 2.3 让 DB 里的 Prompt 真正生效

Prompt 是 DB 驱动的（`seed_default_prompt` 只在表为空时写入），**只改代码无效**。两种方式二选一：

- 管理端「Prompt 管理」页面直接编辑并启用；
- SQL 更新（先查后改，避免覆盖租户自定义 Prompt）：

```sql
-- 1) 查全局默认 Prompt（表名/字段以实际库为准）
SELECT id, tenant_id, key, is_active, LEFT(content, 60) FROM prompts
WHERE tenant_id = '' AND key = 'default';

-- 2) 更新全局默认（content 填 2.2 的完整文本）
UPDATE prompts SET content = ?, updated_at = NOW()
WHERE tenant_id = '' AND key = 'default';

-- 3) 如有租户级 active Prompt，需要单独在其租户下补同样规则
SELECT tenant_id, key, LEFT(content, 40) FROM prompts
WHERE is_active = 1 AND tenant_id <> '';
```

优先级：**租户级 Prompt > 全局默认**。只改全局，对已配置自定义 Prompt 的租户不生效。

### 3.9 踩坑

function renderCitations(container, citations) {
  if (!citations || !citations.length) return;
  if (container.querySelector('.cite-box')) return;   // 防止重复插入

  const box = document.createElement('div');
  box.className = 'cite-box';

  head.className = 'cite-head';
  head.textContent = `参考来源（${citations.length}）`;

  const list = document.createElement('div');
  list.className = 'cite-list';
  list.style.display = 'none';

  citations.forEach(c => {
    const item = document.createElement('div');
    item.className = 'cite-item';
    item.innerHTML =
      `<div class="cite-title">[${c.index}] ${esc(c.title || '未命名文档')}` +
      (c.section ? `<span class="cite-sec"> · ${esc(c.section)}</span>` : '') + `</div>` +
      `<div class="cite-snippet">${esc(c.snippet || '')}</div>`;
    list.appendChild(item);
  });

  head.onclick = () => {
    list.style.display = list.style.display === 'none' ? 'block' : 'none';
  };
  box.appendChild(head);
  box.appendChild(list);
  container.appendChild(box);
}

## 第五章 Step 5：拒答兜底

### 5.1 先承认 R11 的数据结论

- 无答案问题的 dense 相似度中位数约 0.547，而有答案问题的最低分约 0.497 —— **分布重叠**；
- 也就是说：**任何单一阈值都无法同时做到"不误拒"和"不泄漏"**；
- 不同模式分数量纲不同（dense 0.5~0.8 / RRF 0.5~1.0 / rerank 对数似然可负），阈值不能跨模式复用。

所以 R12 的拒答要分三层，阈值只作为辅助。

### 5.2 三层策略

| 层级 | 触发条件 | 动作 | 强度 |
| --- | --- | --- | --- |
| L1 空检索 | 阈值过滤后 0 条 | 直接返回拒答话术，**不进入模型调用**（严格模式） | 强 |
| L2 低分 | top1 < 标定阈值 且命中数少 | 仍进模型，但 prompt 要求"资料不足就说不知道" | 中 |
| L3 无引用/引用非法 | 模型有资料却一个 `[n]` 都没标，或标了不存在的编号 | 用拒答话术替换回答，并记日志 | 强（推荐主策略） |

**推荐主策略是 L3**：它不依赖分数分布，只看"回答是否真的挂了来源"，最直接地对应"答案溯源"。

### 5.3 代码：后置引用校验（L3）

放 [main.py](file:///Users/changwenbiao/PycharmProjects/ai_customer_service/python_agent/main.py) 生成最终回答之后（流式的 `end` 之前、非流式的 return 之前）：

```python
import re
from tools import get_citations

REJECT_REPLY = "这个问题我暂时没有查到准确信息，建议转接人工客服进一步确认。"


def citation_guard(answer: str, citations: list[dict]) -> tuple[str, bool]:
    """返回 (最终回答, 是否被降级为拒答)"""
    if not answer:
        return REJECT_REPLY, True

    # 本次没有检索到任何资料：可能是寒暄、订单查询等非知识库问题，放行
    if not citations:
        return answer, False

    valid = {c["index"] for c in citations}
    used = {int(n) for n in re.findall(r"\[(\d+)\]", answer)}

    # 有资料但没有任何引用 → 视为无依据回答
    if not used:
        return REJECT_REPLY, True
    # 引用了不存在的编号 → 视为编造来源
    if not used.issubset(valid):
        return REJECT_REPLY, True
    return answer, False
```

流式注意：`chunk` 已经把字吐给前端，事后替换会"先说后撤回"。两种处理：

- 简单：校验失败时追加一条系统提示"以上回答未通过溯源校验，请以人工客服确认为准"，并推送 `end` 的 `content` 为替换后的文本；
- 彻底：流式阶段先缓冲（不逐 token 推送），`end` 前校验，再一次性推送。**R12 建议先用第一种**，不破坏现有体验。

### 5.4 可选：进入模型前的硬闸门（L1）

严格实现"资料里没有就不调用大模型"，需要在 Agent 调用前先做一次检索：

```python
ORDER_ID_RE = re.compile(r"\d{6,}")

async def pre_retrieval_gate(tenant_id: str, user_message: str) -> bool:
    """True = 直接拒答，不进入 Agent"""
    if ORDER_ID_RE.search(user_message):        # 订单类问题交给 query_order
        return False
    store = app.state.tenant_stores.get(tenant_id)
    if store is None:
        return False
    pairs = await store.asimilarity_search_with_score(user_message, k=1)
    if not pairs:
        return True
    top_score = float(pairs[0][1])
    return top_score < REJECT_SCORE_THRESHOLD
```

配置（[config.py](file:///Users/changwenbiao/PycharmProjects/ai_customer_service/python_agent/config.py#L43-L69) 检索配置区）：

```python

REJECT_SCORE_THRESHOLD = 0.35        # 仅按 dense 量纲标定，换模式必须重标
```

> 关闭原因要说清楚：`query_order`、寒暄、工单进度这类问题不需要知识库，硬闸门会误拒。
> 面试被问"为什么不直接用阈值"时，用 5.1 的分布重叠数据回答。

### 5.5 阈值标定流程（用 R11 的评测能力）

1. 用 R11 评测集跑 `dense`，导出每条问题的 top1 分数；
2. 把有答案 / 无答案两组分数画分布，找"误拒率 ≤ 5% 时泄漏率最低"的点；
3. 同一阈值不要用到 hybrid / rerank；
4. 上线前用 15 条无答案问题回归，拒答率目标 ≥ 90%，同时有答案问题的误拒率 ≤ 5%。

### 5.6 验收

| 用例 | 期望 |
| --- | --- |
| 有答案 + 带引用 | 正常回答 |
| 有答案但模型没标引用 | L3 替换为拒答，日志记录 `citation_guard=reject` |
| 模型标 `[9]`（不存在） | L3 替换为拒答 |
| 无答案问题 | 拒答 + 引导人工 |
| 订单号问题 | 走 `query_order`，不触发 L1（若开启） |

### 5.7 踩坑

- 寒暄（"你好"）没有引用但 citations 为空 → 放行；一旦当天检索过资料（citations 非空），寒暄也可能被 L3 误杀 → 需要把 L3 作用范围限定为"调用了 search_kb 的轮次"。
- 流式先吐后撤回 → 前端需要展示"已更正"提示，否则用户困惑。
- 拒答话术与结尾固定话术冲突 → 拒答时不要再追加"客服中心 | 工作时间"。

## 第六章 Step 6：数字类事实校验

### 6.1 为什么要单独做

金额、时效、比例是最容易被"参数记忆"污染，也最容易被用户当成承诺。即使整体有引用，句子里数字仍可能是模型自己算的。

### 6.2 规则

- 回答中出现 `天/日/小时/个工作日/元/%/折` 的数字，必须**同句或相邻位置**带 `[n]`；
- 订单相关数字必须来自 `query_order` 返回值，不允许从知识库推断；
- 无法溯源的数字 → 删除该句或整条降级为拒答。

### 6.3 代码（放在 `citation_guard` 之后）

```python
NUM_RE = re.compile(r"\d+(?:\.\d+)?\s*(?:天|日|小时|个工作日|元|%|折)")

def number_guard(answer: str, citations: list[dict]) -> tuple[str, bool]:
    if not citations:
        return answer, False
    ok = True
    for sent in re.split(r"[。！？\n]", answer):
        if NUM_RE.search(sent) and not re.search(r"\[\d+\]", sent):
            ok = False
            break
    if ok:
        return answer, False
    return REJECT_REPLY, True
```

> 规则很陡：一句话里出现两个事实、只有一个引用，也会被判失败。可放宽为"整段至少有一个引用"，但效果会打折；建议先严后松，用评测数据决定。

### 6.4 Prompt 侧配合

在 system prompt 的第 2 条后补充：

```
涉及金额、时效、比例的数字，引用编号必须紧跟在数字所在句子后面。
```

### 6.5 验收

- "退货运费谁承担？" → 有引用，通过；
- "7 天无理由，超过 15 天还能退吗？" → 若资料只写 7 天，模型回答 15 天相关内容必须被拦；
- 订单时效（"我的订单几天到"）→ 必须来自 `query_order` 的字段，不能引用知识库。

## 第七章 Step 7（加分）：自一致性校验

### 7.1 适用条件

只对**高风险问题**启用：金额、时效、退换货政策、涉及承诺的结论。全量启用成本和延迟都不可接受。

### 7.2 做法

同一问题用较高温度采样 3 次，取最终 AIMessage：

```python
async def self_consistency(agent, payload, n=3) -> tuple[str, bool]:
    outs = []
    for _ in range(n):
        result = await agent.ainvoke(payload)
        outs.append(_last_ai_content(result))
    # 归一化：去空白、去标点、去引用编号后再比较
    norm = [re.sub(r"[^\w\u4e00-\u9fa5]", "", o) for o in outs]
    if len(set(norm)) > 1:
        # 任一不一致 → 说明模型对该事实没有稳定把握
        return REJECT_REPLY, True
    return outs[0], False
```

### 7.3 成本控制

- 只对 `number_guard` 命中的问题、或租户配置的高风险意图启用；
- 采样结果可缓存（同问题 + 同知识库版本）；
- 默认关闭，用配置开关 `ENABLE_SELF_CONSISTENCY=false`。

### 7.4 结论怎么写进项目说明

"自一致性只作为离线抽检手段，不做线上主链路"——因为 3 次调用会把 P95 延迟和成本放大 3 倍，而 L3 引用校验已经能覆盖大部分幻觉。

## 第九章 上线顺序、开关与踩坑清单

### 9.1 推荐上线顺序

1. Step 1（编号 + ContextVar）+ Step 2（Prompt）→ 先让回答"看起来有引用"；
2. Step 5 L3（引用校验）→ 先压住"有资料却乱答"；
3. Step 3（Go 透传 + metadata）→ 引用可持久化；
4. Step 4（前端展示）→ 用户可见；
5. Step 6（数字校验）→ 收紧高风险事实；
6. Step 7 视评测结果决定是否做。

### 9.2 开关建议

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `ENABLE_CITATIONS` | true | 关闭后 search_kb 退回纯文本，便于对比 |
| `ENABLE_CITATION_GUARD` | true | L3 后置校验 |
| `ENABLE_NUMBER_GUARD` | true | 数字校验 |
| `ENABLE_PRE_RETRIEVAL_GATE` | false | L1 硬闸门，误拒风险高 |
| `REJECT_SCORE_THRESHOLD` | 0.35 | 仅 dense 标定 |
| `ENABLE_SELF_CONSISTENCY` | false | 成本高 |

### 9.3 回滚

- 前端异常：Go 返回的 `citations` 字段可保留，前端忽略即可；
- 引用校验误杀：先关 `ENABLE_CITATION_GUARD`，保留 Prompt 与编号；
- DB 列出问题：`metadata` 为可空列，不影响旧逻辑读写。

### 9.4 踩坑汇总

| 问题 | 根因 | 对策 |
| --- | --- | --- |
| 回答有 `[1]` 但前端没有来源 | Go 没透传 citations 或历史没查 metadata | 检查 Step 3 三段链路 |
| 引用编号越界 | 模型编造 / 两次检索编号未累加 | 全局编号 + L3 校验 |
| 无答案问题仍有来源 | 检索命中了无关片段 | 阈值 + prompt + L3；评测驱动调阈值 |
| 阈值换模式失效 | 分数量纲不同 | dense/hybrid/rerank 分别标定 |
| 流式回答被替换后前端困惑 | 先吐后校验 | 前端提示"已更正"，或改缓冲模式 |
| 寒暄被误判无依据 | citations 非空时 L3 全量生效 | L3 仅对"本轮调用过 search_kb"生效 |
| 引用 snippet 撑破气泡 | 200 字太长 | 折叠 + `max-height` + 滚动 |

## 附录 B：面试问答

1. **"怎么防幻觉？"**
   → 不是只改 prompt。三层：检索结果编号化（可溯源）→ prompt 强制引用 → 后置引用校验（无引用/编号非法直接拒答）。阈值只做辅助，因为 R11 数据显示有/无答案分数分布重叠。
2. **"为什么不用相似度阈值直接拒答？"**
   → 给出实测分布（无答案中位数 0.547、有答案最低 0.497），说明单阈值必然二选一牺牲；不同检索模式量纲还不同。
3. **"引用怎么保证不是编的？"**
   → 编号由程序分配（ContextVar），模型只能引用检索到的编号；后置正则校验 `[n] ⊆ citations`，越界即拒答。
4. **"流式下怎么处理引用？"**
   → 正文 chunk 先行，citations 随 `end` 下发；校验失败时前端展示更正提示，或改缓冲模式一次性下发。
5. **"自一致性为什么不做线上？"**
   → 3 倍成本/延迟，收益边际；离线抽检用来评估风险，线上主链路靠引用校验。
