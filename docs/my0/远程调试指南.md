# 远程调试指南（线上运行 / 容器调试 / 本地调试）

仓库有三种使用方式，先看选择表，再跳到对应章节。

| 方式 | 适用场景 | Go 跑在哪 | Agent 跑在哪 | 是否支持断点 |
| --- | --- | --- | --- | --- |
| ① 线上运行 | 部署、验收、演示 | 容器（生产镜像） | 容器（生产镜像） | 否 |
| ② 容器内调试 | 复现"只在容器环境出现"的问题、验证镜像 | 容器（dlv 镜像） | 容器（debugpy 镜像） | 是（远程 attach） |
| ③ 本地调试（推荐日常） | 写代码、单步、改完立即生效 | GoLand 本地进程（8082） | PyCharm 本地进程（8000） | 是（本地） |

日常开发用 ③；怀疑容器/环境差异时用 ②；部署验证用 ①。

## 1. compose 文件职责

| 文件 | 角色 | 关键内容 |
| --- | --- | --- |
| `docker-compose.yaml` | 基础编排（必选） | mysql / postgres / qdrant / redis / agent / go / nginx 全套；服务间用容器名互连（`mysql:3306`、`postgres:5432`、`qdrant:6333`、`redis:6379`、`agent:8000`、`go:8080`） |
| `docker-compose.local.yaml` | 本地调试覆盖层（方式 ③ 必选） | ① Redis `6379` 映射到宿主机；② nginx 使用 `deploy/nginx.local.conf`，反代到 `host.docker.internal:8082`；③ 知识库、会话图片目录 bind mount 给 nginx；④ 去掉 nginx 对 go 容器的依赖 |
| `docker-compose.debug.yaml` | 容器调试覆盖层（方式 ② 必选） | go 改用 `Dockerfile.debug`（dlv headless + `SYS_PTRACE`），agent 改用 `Dockerfile.debug`（debugpy），各自暴露 `127.0.0.1:2345` / `127.0.0.1:5678` |

组合规则：

- 覆盖层不能单独使用，必须多个 `-f`，**后加载的覆盖前面的**。
- 方式 ①：只用 `docker-compose.yaml`。
- 方式 ②：`docker-compose.yaml` + `docker-compose.debug.yaml`。
- 方式 ③：`docker-compose.yaml` + `docker-compose.local.yaml`。
- **② 和 ③ 的覆盖层不要混用**，`local` 已经把 agent 指向宿主机，和容器调试互斥。
- `docker-compose.local.yaml` 里的 `!override` / `!reset` 需要 Docker Compose ≥ 2.24（当前 2.31 支持）。

端口总表：

| 端口 | 归属 | 使用场景 |
| --- | --- | --- |
| `8080` | nginx（前端入口） | 全部 |
| `8000` | Agent 业务端口 | ② 容器 / ③ 本地 |
| `8082` | 本地 Go 网关 | 仅 ③ |
| `2345` | dlv 调试端口（127.0.0.1） | 仅 ② |
| `5678` | debugpy 调试端口（127.0.0.1） | 仅 ② |
| `3306 / 5432 / 6333 / 6379` | MySQL / PostgreSQL / Qdrant / Redis | 全部（③ 需要） |
| `8081` | embedding 容器（独立服务） | 与 Go 端口选择无关，但 ③ 不能占 8081 |

## 2. 方式一：线上运行（全部容器）

```bash
docker compose up -d --build
```

- 前端入口 `http://localhost:8080`：`/admin/` 管理端、`/chat/` 聊天端、`/sdk/` 接入脚本。
- 容器内调用链：`nginx → go:8080 → agent:8000`，Agent 再访问 `postgres/qdrant/redis`。
- 此方式**不做调试**，不要叠加 `docker-compose.debug.yaml`（会把 dlv/debugpy 起起来，属于无认证调试端口）。

验证：

```bash
docker compose ps
curl -i  http://localhost:8080/api/auth/tenants
curl -s  -o /dev/null -w "agent:%{http_code}\n" http://localhost:8080/agent/docs
docker compose logs -f go agent nginx
```

注意：

- 线上 `.env` 的数据库密码只在数据卷首次初始化时生效，改密码对已有卷无效。
- 不要执行 `docker compose down -v`（会清空 MySQL / PostgreSQL / Qdrant / Redis 数据卷）。
- 需要临时排查时，切到方式 ②（容器内）或方式 ③（本地），不要在生产容器上长期挂着调试端口。

## 3. 方式二：容器内远程调试

### 3.1 启动调试容器

```bash
# Go + Agent 都进容器调试
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build go agent

# 只调 Go
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build go

# 只调 Agent
docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build agent
```

- Go 镜像内以 headless 方式启动：`dlv --listen=:2345 --headless --accept-multiclient --continue`，容器启动即可服务，IDE 可随时 attach/断开。
- Agent 镜像内以 debugpy 启动：`python -m debugpy --listen 0.0.0.0:5678 main.py`，不阻塞服务启动。
- 两个调试端口只绑 `127.0.0.1`，**禁止改成 `0.0.0.0`**：dlv/debugpy 无认证、无加密。
- 首次构建很慢（Agent debug 镜像会预下载 `bge-reranker-v2-m3`，占用较多磁盘），构建前确认 Docker 有足够空间。

### 3.2 Go attach（GoLand / VS Code）

- attach 地址：`127.0.0.1:2345`，类型 Delve remote。
- 源码映射：**本地 `go_service` ↔ 容器 `/build`**。
  `Dockerfile.debug` 在 `/build` 编译，DWARF 里记录的是 `/build/...`；不要映射到 `/app`（二进制所在目录不是编译目录）。
- `dlv 1.27` 的参数顺序要求 flag 写在 `exec` 之后，Dockerfile 的 CMD 已固定，不用改。
- 断点命中时 Go 进程暂停，经 nginx 的请求会超时/502，属正常现象。

### 3.3 Agent attach（PyCharm）

- 配置：`Run → Edit Configurations → + → Attach to DAP`（PyCharm Community 可用），host `127.0.0.1`，port `5678`。
- 路径映射**顺序很重要**：

  | 容器路径 | 本地路径 |
  | --- | --- |
  | `/usr/local/lib/python3.13/site-packages` | `python_agent/.venv/lib/python3.12/site-packages`（或 conda 环境对应目录） |
  | `/app` | `python_agent` |

  第三方库映射必须排在项目源码之前，否则第三方库里的断点会变成空心斜杠、无法绑定。
- `PYDEVD_DISABLE_FILE_VALIDATION=1` 已在调试镜像里设置，避免源文件校验报错刷屏。
- 同理，断点暂停期间前端请求会等待/超时。

### 3.4 退出容器调试，恢复线上运行

```bash
docker compose up -d --build go agent
```

不带 `docker-compose.debug.yaml` 即回到生产镜像。

## 4. 方式三：本地调试（GoLand + PyCharm，推荐日常）

### 4.1 架构与端口

```
浏览器 http://localhost:8080
     │
     ▼
nginx 容器 (8080→80) ──► host.docker.internal:8082
                                  │
                                  ▼
                  GoLand 本地 Go（127.0.0.1:8082）
                                  │  CS_AGENT_URL=http://127.0.0.1:8000
                                  ▼
                  PyCharm 本地 Agent（0.0.0.0:8000）
                                  │
       ┌──────────────┬───────────┴───────────┬──────────────┐
       ▼              ▼                       ▼              ▼
  mysql:3306     postgres:5432          qdrant:6333      redis:6379
```

- 本地 Go 用 **8082**：8080 被 nginx 占用，8081 被 embedding 容器占用。
- 前端入口保持 `8080`，不需要改习惯。
- Go → Agent：`CS_AGENT_URL=http://127.0.0.1:8000`
- Agent → Go：`GO_BUSINESS_API=http://127.0.0.1:8082`
- nginx → Go：`host.docker.internal:8082`（`deploy/nginx.local.conf`）

### 4.2 启动依赖 + nginx（容器）

```bash
docker compose -f docker-compose.yaml -f docker-compose.local.yaml \
  up -d --no-deps mysql postgres qdrant redis nginx
```

- `--no-deps` 防止 nginx 顺带拉起 go / agent 容器。
- 首次带 local 覆盖启动时 Redis 会因新增端口映射重建一次，数据卷保留。
- 改了 `deploy/nginx.local.conf` 后：`docker exec cs_nginx nginx -s reload`。

### 4.3 停掉容器版 Go / Agent

```bash
docker compose stop go agent
```

否则会和本地进程抢 Redis 队列，调试的也不是实际响应的代码。

### 4.4 GoLand 启动 Go

1. 打开 `go_service` 目录。
2. GOROOT 选本机 Go（一般自动识别；`Settings → Go → GOROOT` 可手动指定 `go env GOROOT` 的输出）。
3. 右上角选 **「Go 本地调试」**，点 **Debug**。
   - 该配置已随仓库提交（`go_service/.idea/runConfigurations/Go_local.xml`），类型 `GoApplicationRunConfiguration`，以 package `customer_service` 运行，工作目录 `go_service`。
   - 若下拉框没有，`File → Reload Project` 或重启 GoLand；也可直接右键 `main.go` → Debug。
4. 启动成功日志为 `Listening and serving HTTP on :8082`。

环境变量来源 `go_service/.env.local`（`config.LoadConfig` 自动加载，容器内无此文件，不影响线上）：

```
CS_MYSQL_DSN=root:<MYSQL_ROOT_PASSWORD>@tcp(127.0.0.1:3306)/cs_biz_db?...
CS_AGENT_URL=http://127.0.0.1:8000
INTERNAL_API_TOKEN=<与根 .env 一致>
MODEL_KEY_ENCRYPT_KEY=<与根 .env 一致，否则模型配置解密失败>
REDIS_ADDR=127.0.0.1:6379
CS_SERVER_PORT=:8082
RSA_PRIVATE_KEY_PATH=<仓库>/data/rsa_private.pem
CS_MSG_FILE_ROOT=<仓库>/data/msg_files
```

### 4.5 PyCharm 启动 Agent

1. 打开 `python_agent` 目录。
2. 解释器选 `python_agent/.venv`（Python 3.12，复用 conda 环境的 site-packages）。
3. 右上角选 **「Agent 本地调试」**，点 **Debug**。
4. 看到 `Uvicorn running on http://0.0.0.0:8000` 即成功。

环境变量来源：`main.py` 先按文件路径加载仓库根 `.env`，再用 `python_agent/.env.local` 覆盖（`REDIS_URL`、`GO_BUSINESS_API=8082`、`KB_FILE_DIR`、`ENABLE_RERANK=false`、`KB_INDEX_WORKERS=1`）。改了 `.env.local` 必须重启 Agent。

### 4.6 验证

```bash
# 本地 Go
curl -i http://127.0.0.1:8082/api/auth/tenants

# 本地 Agent
curl -s -o /dev/null -w "agent:%{http_code}\n" http://127.0.0.1:8000/docs

# 经 nginx 的完整链路
curl -i http://localhost:8080/api/auth/tenants

# 依赖连通性
nc -z 127.0.0.1 3306 && nc -z 127.0.0.1 5432 && nc -z 127.0.0.1 6333 && nc -z 127.0.0.1 6379 && echo deps ok
```

### 4.7 IDE 配置已入库

`/.idea`、`go_service/.idea`、`python_agent/.idea` 的共享文件（run config、iml、modules、代码风格、inspection）已纳入仓库，clone 后不用重建运行配置。但每台机器仍需要一次性准备：

1. `cp .env.example .env` 并填密码/密钥（`.env` 含敏感值，不入库）
2. `cp go_service/.env.local.example go_service/.env.local`
3. `cp python_agent/.env.local.example python_agent/.env.local`
4. 本地创建 Python 虚拟环境（`.venv` 不入库），PyCharm 里选一次解释器
5. 启动依赖 + nginx（见 4.2）

说明：

- `workspace.xml`（三个 `.idea` 目录各一份）故意不入库：它存窗口状态、最近打开文件、临时运行配置，跨机器没有价值且必然冲突。
- `python_agent/.idea/misc.xml` 里的解释器名带绝对路径，clone 到同一路径可直接用；换机器/路径时 PyCharm 会提示解释器无效，重选一次即可，run config 用的是模块解释器，不需要改。
- GoLand 的 GOROOT 是本机全局设置，`go_service.iml` 用 `inheritedJdk`，GoLand 会自动识别。

## 5. 模式切换速查

| 从 → 到 | 操作 |
| --- | --- |
| 线上 → 本地调试 | 执行 4.2（`up -d --no-deps … nginx`）→ `docker compose stop go agent` → IDE 启动两个进程 |
| 本地调试 → 线上 | `docker compose up -d --build go agent nginx`（不带 local 覆盖） |
| 线上 → 容器调试 | `docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build go agent` |
| 容器调试 → 线上 | `docker compose up -d --build go agent` |
| 容器调试 → 本地调试 | 先回线上（上一条），再按 4.2 / 4.3 执行 |
| 本地调试 → 容器调试 | 先停本地 Go/Agent 进程，再按上一条启动 debug 容器 |

## 6. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `GET /api/...` 返回 **502 Bad Gateway** | nginx 仍用基础配置（upstream `go:8080`），go 容器已停 | 用 local 覆盖重建 nginx：`docker compose -f docker-compose.yaml -f docker-compose.local.yaml up -d --no-deps nginx`，确认挂载为 `nginx.local.conf` |
| `dial tcp host.docker.internal:8000: connection refused` | 本地 Agent 没起来（启动顺序问题） | 先起 Agent 再发消息；`lsof -iTCP:8000 -sTCP:LISTEN` |
| `dial tcp ...8082: connection refused`（本地 Agent 调 Go） | Go 没起来，或 `GO_BUSINESS_API` 不是 8082 | 检查 GoLand Debug 状态；检查 `python_agent/.env.local` |
| 容器调试时日活请求超时 / 502 | 断点暂停导致进程停住 | 继续运行即可；或在复现完成后再下断点 |
| 2345 连不上 | 未使用 debug 覆盖层，或容器没重建 | `docker compose -f docker-compose.yaml -f docker-compose.debug.yaml up -d --build go` |
| 5678 attach 后断点不命中 | 路径映射缺失/顺序错误 | 先映射 `site-packages`，再映射 `/app → python_agent` |
| MySQL 认证失败 | `.env` 是 CRLF（值尾部带 `\r`），或密码对已初始化卷不生效 | 转 LF；不要改已有卷的密码 |
| 登录页图片/知识库文件 404 | nginx 未挂载本地目录 | 确认 nginx 已用 local 覆盖重建，检查 `docker inspect cs_nginx` 的 Mounts |
| 本地 Go 起不来提示端口占用 | 8082 被其他进程占用 | `lsof -iTCP:8082 -sTCP:LISTEN`；不要用 8080/8081 |

## 7. 通用注意事项

- **不要 `docker compose down -v`**：会删除 MySQL / PostgreSQL / Qdrant / Redis 的全部持久化数据。
- **调试端口只绑 127.0.0.1**：dlv（2345）、debugpy（5678）无认证无加密，禁止暴露公网。
- **`.env`、两个 `.env.local` 不入库**：`.gitignore` 忽略 `**/.env.local`，`.dockerignore` 也已排除，不会打进镜像。
- **`.env` 必须 LF 换行**：CRLF 会让密码末尾带不可见 `\r`。
- **本地 `data/` 已忽略**：RSA 私钥（`data/rsa_private.pem`）与消息图片（`data/msg_files`）不随仓库分发，首次启动自动生成/创建。
- **本地默认关闭 rerank**（`ENABLE_RERANK=false`）：验证 rerank 效果时改 `true` 并安装 `FlagEmbedding`。
- **Linux 上 `host.docker.internal` 需要 `extra_hosts: ["host.docker.internal:host-gateway"]`**；macOS Docker Desktop 自带。
